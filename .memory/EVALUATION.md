# EVALUATION —— 超级大脑 v2.1 架构合理性评估（对标主流记忆方案）

> 评估时间：2026-11-05 ｜ v2.2 增量补充（用户控制/可视化/索引化）：2026-11-06 ｜ 对标对象：Mem0、Letta/MemGPT、Zep/Graphiti、LangMem、
> OpenAI ChatGPT Memory、腾讯系（ima 知识库 / 元宝长期记忆 / 腾讯云 ES 记忆方案）

## 一、定位判定

本系统是**个人 / 小团队本地优先的"记忆操作系统"**：单机嵌入六引擎 + 事件溯源跨设备同步 +
情绪维度 + 量化遗忘。与 Mem0（云原生 API 层）、Zep（企业级时序图谱服务）、
腾讯（生态内 RAG 知识库）不在同一赛道，属于"Own your memory"路线。

## 三、相对主流方案的差异化优势

1. **事件溯源是唯一真源**：写入先落 NDJSON journal（fsync 后回执），六引擎只是投影。
   换设备、换引擎开关、数据损坏都可重放重建 —— Mem0/Zep 的存储是终态，删了就没了。
2. **双时态 + 合规封存**：knowledge 被推翻时 valid_to/tx_to 打点而非删除，可回答
   "我上周认为什么"——与 Graphiti 同级，强于 Mem0。
3. **情绪是记忆的一等公民**：PAD 三维入库 + Agent 情绪基线（低通滤波）+ 冷静期召回折扣。
   主流方案全部缺失；这是"像人"而非"像数据库"的核心差异。
4. **量化遗忘**：FSRS 幂律衰减 + 可提取性阈值归档，而不是"LLM 决定忘什么"的黑盒。
5. **零 API 依赖可完整运行**：本地 0.6B 抽取 + 规则兜底，云端大模型可选增强。
6. **检索事件可视化**：突触激活星云让"为什么召回它"可观测；星云布局本身也是信息
   （环=分层、扇区=类型、角度=时间），并能下钻到检查器看来源/双时态/审计。
7. **用户控制闭环不牺牲可追溯性**：纠正产生新版本并封存旧版本（before/after 就地可查），
   遗忘只做「移出推理路径 + 保留审计」。主流方案里 Mem0 是改写、ChatGPT 是直接消失，
   都答不了「我上周认为什么、谁改的」。且这套控制**复用既有 7 类事件**，跨设备重放免改造。

## 四、诚实短板（按影响排序）

1. **抽取质量上限**：本地 0.6B 的实体/关系抽取明显弱于 Mem0 用 GPT-4 级模型；
   规则兜底覆盖常见句式，复杂陈述会漏抽。→ 缓解：LLM 通道可切云端强模型（已支持）。
2. ~~**无 LLM 语义合并**~~ → **已补齐（2026-11-05）**：`brain/memory_consolidator.py`
   写入时召回最相似旧记忆（向量+FTS 滑窗探测），LLM 裁决 add/update/merge/skip（Mem0 式），
   update/merge 自动封存被替代记忆；LLM 失败兜底为 add，丘脑去重仍是第一道防线。
   测试 `tests/test_semantic_merge.py`（脚本化 LLM 控制裁决结果）。
3. **单机规模上限**：SQLite/Lance 单文件面向个人量级（百万级记忆可行），
   多用户高并发是腾讯云方案的主场，不是本系统目标。
4. ~~**主题演化弱**~~ → **已补齐（2026-11-05）**：夜间巩固对聚出的主题簇由 LLM 生成主题摘要，
   以「【主题摘要】」记忆走完整写入流入库（可召回、可可视化点亮）；LLM 不可用退化规则拼接。
   金字塔 worldview 层仍保留人工确认。
5. **生态早期**：MCP 通道刚接通，Mem0/LangMem 有现成框架集成与社区。
6. **评估盲区**：golden set 较小；P95/召回率未在十万级以上库复测（本次只做了倒排索引与缓存等
   结构性优化，没有十万级真实库的实测数字）。
7. **敏感分级只是"上下文遮蔽"**：标记位 + 列表/召回默认 `••••••`，正文仍明文入库。
   要满足真正的隐私要求需要字段级加密或按命名空间分库，当前没做（诚实标注）。
8. **遗忘不是"彻底抹掉"**：tombstone 保证推理路径消失 + 审计保留，但合规硬清除
   （GDPR 式物理抹除）需要跨向量/图谱/时序/KV 的 purge 流，尚未实现。
9. **GPU 结论只到「运行时就绪」**：本机 GTX 1060 6GB 已具备 CUDA provider 与 llama.cpp GPU 构建，
   三通道权重齐全，但 `verdict` 仍以实跑为准；6GB 同时挂三模型可能落 `GPU_PARTIAL`，
   便携目录换机后的复跑也还没做。

## 五、结论与路线建议

- **合理性：成立**。六引擎分工没有冗余（关系=事实源、向量=联想、图谱=关联、
  KV=状态、时序=轨迹、超图=高阶），事件溯源让"本地优先 + 多端 + 可回放"三者自洽。
- ~~**最值得抄 Mem0 的一课**~~ → 已落地：`merge.merge_enabled` 可关闭，候选条数可配（设置页「语义合并与聚类」组）。
- **最值得抄 Zep 的一课**：edge invalidation 的自动失效传播（图谱关系随事实更新自动失效）。
- **不建议追**：多租户 SaaS 化（偏离定位）；先把 MCP 推给 WorkBuddy/CodeBuddy/DSH 实际使用，
  用真实流量回填评测集。
- **v2.2 已补齐的第三块短板**：用户控制（纠正/封存/遗忘 + 审计）与可视化下钻已落地，
  产品叙事从「记忆库」变成「可被用户管住的记忆」——这是 Mem0 之外最常被诟病的一环。
